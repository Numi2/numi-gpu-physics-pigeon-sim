# Perched q/v reconstruction: drive target observer

The read-only native observer reproduced every replay frame from the original v3 development trajectory for the first 210 frames exactly. At the reconstructed perched q/v start, the first logged leg position targets differed sharply from the source trajectory: for example the knee target was 0.280 rad versus approximately 0.415 rad in the source; first-substep leg efforts saturated at +/-0.75 and +/-0.60, while the corresponding late source efforts were much smaller. The recorded q/v and selected status bits do not restore all the controller state. This supports the conclusion that the reconstructed state is not a faithful checkpoint; it does not yet identify which missing state produced the target change. The attempted phase and history controls in the preceding results did not fix the kick. No policy is trained from the reconstructed perched state.

The two instrumented full logs, commands, replay traces, input hashes and observer build record are in `crow-drive-target-probes-20261115.tar.gz`, SHA-256 `469b0c699678bc6acc89b95904b6a9a1143114e6f52e97bfc8db4c5347bbd63f`. These development probes are not an autonomous landing.
