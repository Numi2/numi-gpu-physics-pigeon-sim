# Coordinate encoding control for native elastic-force reference

Question: can world-coordinate encoding alone introduce force errors of the observed scale? Use the identical 9-node initial shaped rod at x offsets 0, -0.0125 and +1 m, before any simulation, with the same model and native CPU elastic-energy finite-difference instrument. Compare exact double positions with (a) independently FP32-rounded absolute coordinates and (b) a two-FP32 high/low encoding, reconstructed for this CPU instrument in double. For each offset, compute all free-node xyz force differences relative to the exact unrounded state using gradient steps 3e-9, 1e-9 and 3e-10 m. Predeclared predictions: the +1 m ordinary-FP32 maximum force error exceeds 0.01 N; the high/low maximum force error at each offset is below 0.0001 N; and all reported force-error comparisons are resolved across the step-size variants within 0.001 N. Record all source inputs, exact/encoded states, force arrays, binary hashes and failures. This is an encoding-only CPU control, not a GPU compensated-arithmetic implementation or a corrected physics trajectory; hidden high bits cannot be recovered from existing rounded world states. No timestep changes and no inference of feather or flight qualification.
