# Supported-rod resident rollback and continuation

The preregistered resident test passed for this fixture. An ordinary c=100 step succeeded; tightening only the second submission's quality feasibility tolerance to 1e-12 produced a dispatched GPU rejection (status 11, zero successful steps, one failure). The returned articulated q (188 bytes), v (184 bytes), rod node state (288 bytes), and rod edge state (128 bytes) matched the preceding accepted output byte for byte. Restoring the normal tolerance produced a successful third submission whose same state components matched an independent two-success control bit for bit. Both independent initial accepted states also matched. The full output byte strings and analysis are retained. `published=true` correctly denotes returned diagnostics and restored state, not step success.

The scene-body vector was empty, so its equality is vacuous. Internal manifold caches, rod witnesses, mutable inactive buffers and any checkpoint envelope were not compared. The fixture has one rod, world-fixed supports, no active contacts, no moving endpoint and no CCD; it does not establish rollback for other world configurations. The owner checkpoint API explicitly excludes rod worlds and qualityNewton in this configuration, so this is direct resident-boundary and continuation evidence, not byte-exact checkpoint API qualification. The candidate remains experimental.

The first attempt to generate the test source stopped with a Python `ValueError: substring not found` because the source marker included a nonexistent preceding space; no native run occurred. The checked-in `make-probe.py` corrected the marker. No simulation timestep was changed.
