# Refinement bypassed the hard-equality rejection

The unchanged native quality probe failed its path assertion. An instrumented copy established why the hard-equality gate did not prevent publication: both direct and PCG requests returned `SUCCESS` on the expanded-refinement path, with reported hard-equality residuals 0.0643502 and 0.0650407 against a 0.00002 feasibility tolerance. The fixture itself also marks a positively regularized scalar as hard and expects an unrefined path, so its old path assertion does not isolate the defect. This result confirms a real acceptance bypass; it is not a successful hard-constraint solution.

In `mrUnifiedQualitySolveWithWorkspace`, the FP32 solver's failure can enter expanded refinement. Its candidate is audited for optimality and cone feasibility, but the hard-equality scalar `candidateScalars[3]` is only copied into the success record, never compared with the hard-equality tolerance. The narrow safety repair is to apply the same hard-equality test before publication on the refined path. A native Metal regression must show rejection above tolerance and continued acceptance of a valid compliant control; preserve this failure and the initial instrumented-probe compile failure. This guard closes a bypass but does not make the penalty method an exact hard-constraint solver.
