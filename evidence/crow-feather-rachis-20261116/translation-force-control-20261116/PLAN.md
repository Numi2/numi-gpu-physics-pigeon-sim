# Translation control for FP32 force sensitivity

Hypothesis: the x-force screen depends on absolute coordinate magnitude because the world stores rod positions in FP32; alternatively, a translation-invariant physical/model error should not improve merely by translating the whole unchanged fixture. At the same 1 ms timestep use the archived damping-consistent candidate and the identical 9-node fixed-support fixture, translated rigidly along x by -0.0125 m (rod centered on zero) and +1 m. Match each to the first ten states of the retained zero-offset controls, at damping 0 and 100. Translate both the initial rod and its fixed target positions; change no material, dynamics, controls or other setup. Run ten accepted steps per condition; compare all free-node xyz force residuals using the previously specified backward-difference metric and native CPU energy, same 0.01 N bound. Register as predictions: (1) each centered arm's 10-step maximum is lower than its matched origin arm; (2) at +1 m each arm's maximum is larger than its corresponding origin arm, or the native step fails due to precision. Failed steps, unchanged or worse centered results and missing/nonfinite data remain failures or inconclusive, not discarded. Record success statuses, full positions/velocities, input identities, all force components and residuals, and source/patch hashes. Evaluate CPU elastic-energy force at h=1e-9 m using the same native model; any threshold conclusion at an extreme must additionally be checked at 3e-9 and 3e-10 m. No timestep adjustment. This is a numerical translation sensitivity test, not physical or biological qualification, nor proof that unknown unrounded coordinates had any particular value.
